- **Tool**: Claude Code.
- **Why I used it**: With P-002's real design and real tokens in place, this was the first pass that makes the app visually usable end to end, letting the owner (and evaluators) click through the whole product before any backend exists.
- **AI's approach/output**: Entered Plan Mode, then built: real brand SVG assets (stripped of embedded C2PA provenance metadata, ~8KB→~500 bytes each) and real design tokens in `tokens.css`; a mock layer (`mocks/users.js`, `session.js`, `dashboardData.js`) and an extended `lib/api.js` (`login`/`activateAccount`/`getMe`/`logout`/`getDashboard`, client-side rate limiting after 5 failed attempts, `ApiError`); reusable UI atoms (`Button`, `Input`, `StatusPill`, `StatCard`, `WeekStrip`, `Skeleton`, `EmptyState`, `PageHeader`); the full 10-section landing page ported component-by-component from the real `.dc.html` source with its GSAP/ScrollTrigger/Flip motion (M1–M9); `/login` and `/activate` (with a clearly-labeled mock demo-accounts panel and a mock-token invite lookup); an app shell with role-filtered navigation and three real dashboards (admin/manager/employee) built on live mock data via TanStack Query; a real interactive check-in/elapsed-timer control on the employee dashboard; real Privacy/Terms pages and an on-brand 404; and ADR-026 (account-activation flow instead of public sign-up, per the prompt's own locked decision).
  Manual browser testing (Chrome, via the browser automation tools) surfaced a real defect — `window.gsap`/`window.ScrollTrigger`/`window.Flip` references left over from the original CDN-script-based design source, which silently no-op against the npm-imported modules the real app actually uses — logged and fixed as AICR-002 in `docs/AI_CODE_REVIEW.md`, with a new rule added to `AGENTS.md` §6 to catch this pattern on future design ports.
  A first Lighthouse run against the production build scored Performance 81 (Accessibility 97, Best Practices 100, SEO 100), short of the P2 ≥90 target, for exactly the reason the design's own handoff notes had flagged (GSAP+ScrollTrigger+Flip plus two Google Fonts families). Fixed with two changes — route-level code-splitting (`React.lazy` in `App.jsx`, keeping the landing bundle free of auth/dashboard code) and switching the Google Fonts `<link>` from render-blocking to a preload-and-swap pattern — without dropping any library. Final scores: Performance 93, Accessibility 97, Best Practices 100, SEO 100.
  Also verified in-browser: role-based nav filtering (employee sees no Employees/Approvals/Audit; manager sees no Employees/Audit), the check-in interaction flipping real local state, `/activate` with and without a token, the 404 route, and the mobile nav drawer/hamburger menu at a narrow viewport. One environment caveat worth recording: the automated browser tab used for testing reports `document.hidden = true` (no real OS focus), which throttles `requestAnimationFrame` and made GSAP timelines (hero story, StatCard count-ups) appear to progress very slowly during testing — confirmed via longer waits that they do complete, and this is a testing-tool artifact, not an app defect; a normally-focused tab is unaffected.
